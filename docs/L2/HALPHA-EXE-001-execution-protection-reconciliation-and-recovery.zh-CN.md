# Halpha 交易所动作执行原则

**文档编号：** HALPHA-EXE-001  
**层级：** L2  
**语言版本：** zh-CN  
**上位文档：** HALPHA-CON-001、HALPHA-FLOW-001、HALPHA-ARC-001  
**本文档负责：** 交易所动作责任、唯一提交、防重复、未知结果、保护和核对  
**本文档不负责：** 策略、计划与激活生命周期、资金计算、事实定义、页面和当前场所配置

## 1. 唯一职责

EXE 拥有 Halpha 发起的每个交易所变更请求从本地建立动作责任、向交易所提交、查询与事实核对到明确闭合或交给用户的唯一处理责任。计划、页面、任务、日志和供应商缓存不能替代或推进该责任。

## 2. 先持久化责任，再请求交易所变更

每个拟执行动作最多建立一个稳定动作责任。任何交易所变更请求都只能在该责任成功持久化之后发起；调用前重新读取当前计划、CAP 检查、事实和停止结果。

同一来源和内容重复时返回原责任；身份相同但内容冲突时拒绝。真实资金环境同时只允许一个 Halpha 执行者发起交易所变更请求，无法证明唯一性时不发起新请求。

## 3. 结果与未知

外部调用只有三类业务结论：能够证明没有外部变化；能够由稳定身份和事实确认结果；或者结果未知。超时、断线、崩溃、部分响应和金额较小都不能被猜成成功或失败。

结果未知时按动作可能已经发生处理；默认只查询原外部身份，不为继续原业务意图创建第二动作或改换条款。受影响新增风险停止；可靠查询、已有保护、退出和用户接管继续。

只有既有风险控制责任可能长期不能阻止风险时，才允许一个有界的后继例外：等待并查询原身份后，同目标撤单必须有后续权威事实证明目标订单仍在工作，只减仓市价退出必须有新鲜、可归属的单向残余持仓事实。后继明确引用原责任且每个原责任最多一个，后继不能再产生后继；后继结果未知时停止自动交易所变更请求并交给用户接管。该例外不适用于入场、新建或移动保护、止盈、改单和以新订单替代未知条款。

后继已持久化但能够证明从未调用交易所时，提交前事实变化可以使该本地记录终止，并按最新事实建立替代记录；这些本地替代中仍最多只有一个能够进入交易所调用。后继已经权威闭合后才出现的、精确归属同一激活的新入场成交，不属于未知后继链；计划最多形成一次独立只减仓清理动作，其数量不得超过这些新增成交与当前可归属残仓的较小值。该清理动作未知、部分完成或已经建立后，不释放新增成交预算，也不能产生后继。

部分成交、迟到成交、费用和场所修正都关联原动作。除上述 EXE 风险控制后继外，正常业务需要撤销、补保护、减仓或退出时，由计划形成新的明确动作，而不是修改或重发原动作。

## 4. 保护与闭合

风险出现后，保护是持续责任。只有场所事实能够证明保护实际有效；“已经提交”或页面成功不能替代。保护缺失、冲突或未知时停止受影响新增风险，并优先处理保护、减仓、退出或用户接管。

“用户接管 Halpha 原责任”和“Halpha 接管既有外部仓位”是相反方向的两种交接，界面、命令和事实不得混用。观察到外部仓位只建立账户事实和接管资格判断，不建立 Halpha 入场动作、成交、策略收益或保护责任。Halpha 接管既有外部仓位只有在用户显式确认、最新完整账户快照仍成立、全部普通与条件开放委托已核对、账户与工具归属无冲突、保护和退出条款已固定、CAP 证明后续动作只保护或减少该既有敞口，并且当前执行凭据与写边界能够实际管理该账户时才可生效；任一条件缺失时保持“外部未管理”或“仅观察”，不能显示为已接管。

有效外部仓位接管保留原外部入场来源和接管时基线，不补造 Halpha `ENTRY`。接管后的动作范围从保护、撤销已核对委托、减仓和退出开始，不取得追加同向仓位或重新解释接管前盈亏的权利；接管前后结果必须分界，且账户净仓仍不能代替精确管理责任。只读凭据可以形成接管资格与阻断原因，但永远不能使接管生效。

针对外部仓位形成的减仓或平仓处置责任只消费计划固定的基线数量和目标数量。每次真正提交前，EXE 必须刷新同账户、同工具和同持仓侧的权威事实，扣除本处置计划已经确认的减仓成交后得到应有账户数量，并与交易所当前数量严格一致；动作使用显式数量和场所能够证明的只减仓语义：单向 `BOTH` 使用场所 `reduceOnly`，双向 `LONG | SHORT` 使用场所强制的持仓侧参数并固定为对应侧。数量漂移、开放委托冲突、凭据无写权限或当前持仓模式不能可靠表达同侧只减仓时不提交。处置责任不装载入场处理器，也不能在失败、重启或部分成交后形成追加仓位。

自动减仓、退出和闭合使用的持仓事实必须精确匹配当前环境、场所、账户、工具、查询来源、截止点和数量，并能由该激活的成交事实解释。存在尚未解决的外部活动冲突时，不得只因账户净仓数值碰巧相同就猜成 Halpha 持仓而自动全仓退出或闭合；目标激活成交账、同范围全部激活合计、交易所净仓和开放订单身份仍能同时严格核对时，账户级 `NEW_RISK` 停止继续有效，但不得阻断该激活已有保护、有界只减仓、既定退出和责任闭合。无法完成上述核对时保持未知，或由用户通过正式接管命令承担剩余责任。已经精确绑定原 Halpha 动作的数量异常或终态后迟到成交只停止新风险，不等同于无法归属的外部活动；在完整归属仍成立时应保留保护和有界只减仓能力，且不得覆盖同账户已有的外部活动冲突。

交易所把同账户同工具的多个同向计划合并为一个净仓时，每个计划只能按自身动作与成交事实推导的剩余数量保护、止盈、减仓、退出或撤销自身订单。全部计划推导持仓之和必须与交易所净仓核对；任一计划的减仓数量不得超过自身剩余量和交易所同向净仓的较小值。反向计划、归属冲突或合计不一致时不以交易所净仓替代计划数量。

EXE 把外部活动冲突和已归属动作异常交给 CAP 形成有效停止，但不拥有停止版本或释放决定。动作闭合、用户接管或 CAP 释放账户级系统停止都不改写既有动作责任，也不使 EXE 自动恢复提交；以后只有新的有效计划责任并重新通过当前事实和 CAP 检查，才可能形成新动作。

动作只有在能够证明未产生变化、实际结果及影响已经核对，或剩余责任已明确交给用户时闭合。计划结束、订单局部终态和进程停止本身都不能关闭动作责任。

## 5. 系统交接与复杂度

SYS 拥有运行实体、唯一交易所请求执行者和重启组合顺序；EXE 在恢复时只负责读取未闭合动作、查询原身份并返回本领域结果，不复制系统恢复流程。

应用版本升级不改变已持久动作的身份、条款、状态或责任。恢复必须先读取全部未闭合动作并按其原客户端身份查询；批量场所历史只补充当前核对，不能因为旧终态订单在升级后再次被场所回放，就把数据库仍可识别的 Halpha 动作降级成外部活动，也不能把已经证明终态且无成交影响的历史回放当成当前账户新增风险。当前开放订单、当前持仓和未闭合原身份不受历史查询窗口限制，仍必须单独核对。

执行者连续性丢失后，已有风险责任保持暂停且不会因进程重新出现而自动恢复新增风险。唯一 EXE 完成原身份恢复后，必须以暂停后取得的新鲜账户持仓查询证明目标激活虚拟持仓、全部激活合计、交易所净仓及本账户订单身份一致；页面只消费该事实形成的摘要，用户不能填写或替换恢复证据。恢复命令提交时重新取证，事实过期、动作结果未决或归因不一致时拒绝恢复。

用户接管可以交出从未调用动作的提交责任，也可以交出已经调用但仍无法取得权威结果动作的自动核对责任。接管停止该计划新的 Halpha 交易所变更请求，但不把未决结果写成成功、失败或未成交；原动作身份、调用证据和已有事实继续保留，迟到事实仍归入原动作。已经确认在交易所开放或已有外部影响的责任继续只读核对，直到场所事实终结或用户承担的处置结果可见。

EXE 保持一个动作责任模型和一条交易所变更请求路径，不建立提交尝试、保护任务、核对事项、通用重试或恢复平台。详细状态、字段和场所映射进入 L3，当前范围进入 L4。
