# Halpha 激活资金检查契约

**文档编号：** HALPHA-CAP-002  
**层级：** L3  
**L3 类型：** DOMAIN  
**主要语义所有者：** CAP  
**所属实现模块：** capital 的确定性检查与停止状态能力  
**语言版本：** zh-CN  
**上位文档或条款：** HALPHA-CAP-001  
**直接依赖：** HALPHA-TRADEPLAN-002、HALPHA-DAT-002、HALPHA-EXE-002  
**直接消费者：** HALPHA-EXE-002、HALPHA-SYS-002、HALPHA-UX-002  
**适用纵向约束：** HALPHA-SYS-001、HALPHA-ENG-001  
**本文档负责：** 读取激活资金边界并对动作分类、计算和检查，以及持久化和释放最小停止状态  
**本文档不负责：** 定义激活字段或生命周期、生产场所事实、授予用户决定、执行场所动作和选择当前金额

## 1. 设计结论

CAP 拥有两项边界明确的能力：确定性动作检查，以及按账户或激活保存的最小追加式停止版本。对于半自动计划，检查读取 TRADEPLAN 已固定的交易金额、动作范围、CAP 当前停止版本和 DAT 当前事实，返回确定结果；消费方把检查结果持久化到自己拥有的动作或计划记录。停止、升级和释放在本地事务中追加新版本，不改写历史，也不形成账户额度、资金分配或机器授权。

资金仍留在交易所账户中。检查结果不构成交易所冻结、账户分配或损失保证。

## 2. 输入与输出

动作检查输入包括激活身份与版本、环境和账户、适用工具、计划交易金额、允许动作和期限、当前适用的停止版本，以及当前持仓、开放订单、在途动作、余额、价格、数量、费用和场所规则等必要事实。

结果为：允许增加风险、允许不增险动作、拒绝，或未知。每个结果带稳定原因和事实截止点。CAP 不返回新的授权对象，也不把一次检查结果保存成第二审批状态机。

停止变更输入必须绑定环境、账户、作用域、来源、当前版本和证据摘要。账户级系统停止释放还必须绑定当前停止的版本、内容摘要和来源、用于解决问题的激活、用户明确确认，以及完全由服务端当前事实生成的核对摘要；浏览器和调用方不得上传、替换或自行声明这些证据。

## 3. 动作分类和检查

增加或可能转换风险的动作，必须满足激活有效、未停止新增风险、动作属于范围、事实当前、单动作和累计敞口不超过该计划的交易金额与保证金边界，以及场所当前可承载。当前账户事实必须证明保证金模式为场所支持的 `CROSSED | ISOLATED` 之一；两种模式都可运行，Halpha 不切换保证金模式或自动追加保证金设置。检查采用不高于 5 倍的保守杠杆计算，但不要求用户把交易所实际杠杆设置成 5 倍。

全仓模式下，计划仍只拥有精确绑定该激活的订单、成交、费用和动作责任；账户可用保证金、总持仓和总权益只用于场所承载与冲突检查，不能被拆分或推测为本次计划资产。逐仓模式也沿用同一归因链路，不把交易所逐仓容器当作 Halpha 的计划账本。任一模式下，计划交易金额、保证金上限和归因盈亏都不是交易所冻结额或最大损失保证。

同账户同工具存在多个同向激活时，新增风险检查把全部激活的开放与在途增险责任计入账户承载，同时仍分别约束每个激活的计划金额。保护、止盈、减仓和退出以目标激活由成交事实推导的剩余虚拟持仓为上限，不因交易所合并净仓而取得其他激活数量；目标数量、全部激活合计或交易所净仓任一未知或冲突时拒绝依赖该归属的动作。

只有能够基于当前持仓、开放订单和最坏可执行数量证明不会反向开仓的撤销、保护、减仓和平仓，才按不增险处理。无法证明时返回未知，不允许发起交易所变更请求。

`PositionAlignmentSpec` 的 `REDUCE | CLOSE` 只有在计划基线、最新完整账户快照、同侧当前持仓和已经确认的本处置成交能够精确回算一致，且场所请求以显式数量保持只减仓时，才属于允许不增险动作。请求数量不得超过尚未完成的处置数量或交易所当前同侧仓位；开放普通、条件或算法委托未核对、同范围已有激活、事实过期、账户或工具不符、持仓侧语义不受当前执行路径支持时返回未知。`ADD` 不属于该动作目录，必须作为普通计划的新增风险重新完成全部资金和保护检查。

TRADEPLAN 形成动作意图时调用一次；EXE 向交易所提交变更请求前刷新事实并调用同一函数。后一次可以否决前一次，但不创建第二审批或记录。

## 4. 账户级系统停止与释放

EXE 发现无法归属的外部活动，或发现已经精确归属到 Halpha 动作的数量异常时，CAP 分别以 `SYSTEM_EXTERNAL_ACTIVITY` 或 `SYSTEM_ATTRIBUTED_ACTION_ANOMALY` 追加账户级 `NEW_RISK` 停止。同一未解决期间的同源重复事实不递归增加版本；动作异常可以升级为外部活动冲突，但不能覆盖或降级既有外部活动停止。新增停止必须保留同账户其他停止类别、释放规则和损失闩锁。

这两类系统停止只能通过显式人工释放。服务端必须在同一事务中的当前账户范围重新核对，并同时满足：

- 当前停止仍与预期版本、内容摘要、来源和账户一致；
- 作为解决依据的已有激活属于同一账户，已在该停止之后完成正式用户接管和闭合；
- 一个新鲜、统一截止点的权威账户查询证明账户内全部持仓为零，普通订单和条件或算法订单都为空；
- 同账户不存在任何未完成激活，且该账户全部执行动作均处于 `CLOSED | NOT_SUBMITTED | HANDED_OVER`；
- 账户快照之后没有任何新的账户场所事实，证据未过期且没有时间倒退。

任一项缺失、未知、过期或在并发中变化都拒绝释放。成功时 CAP 追加来源为 `USER_SYSTEM_STOP_RELEASE` 的新版本，只移除这次系统停止对应的 `NEW_RISK`，保留其他停止类别和损失闩锁，并引用被释放版本及服务端证据摘要；历史由前序版本保留，不递归嵌入新版本。相同请求身份返回原结果，身份绑定不同则冲突。

当前受支持的正式释放路径只以“已有激活完成用户接管并进入已闭合状态”为解决依据。外部活动停止如果没有能够按既有 TRADEPLAN、EXE 和 DAT 责任闭合的激活，继续失败关闭且不提供正式释放入口；不为这一少见情形新增账户核对状态机或人工证据旁路。快照之后出现任何新的账户场所事实，都必须重新取得完整账户快照，不能只补查或沿用旧摘要。

释放只是本地停止状态变化，不恢复或重建激活，不启动计划，不产生 EXE 动作或交易所变更请求。任何后续新增风险仍须从当前计划、事实和停止状态重新完成动作检查。

## 5. 建仓损失预算

计划中的允许损失值是资金边界输入：策略计划可以用它计算建仓数量；新建直接执行计划可以把服务端按全部档位、预计入场/退出手续费编译的最大预计亏损传入同一检查。它不是交易所止损、最大损失保证或运行中累计盈亏熔断。CAP 不根据没有生产消费者、缺少统一截止点或归属不完整的盈亏字段停止或恢复新增风险；界面和 API 也不得把这类字段描述成已经生效的运行时保护。直接执行运行时对部分成交后的止损预算约束属于 TradePlan/EXE 的保护责任，CAP 只检查形成和提交增险动作时的当前资本承载，不重复建立第二套盈亏状态机。

运行中风险由计划交易金额和保证金上限、当前保证金模式下的账户可承载事实、场所确认的保护、减仓与退出责任共同约束。本契约不支持按已实现盈亏、未实现盈亏、资金费和手续费形成运行时停止；引入该能力必须先有同一激活归属、统一事实截止点和重启可恢复的生产消费者，不保留无调用方的损失状态机。

## 6. 故障与验证

数据库不可用、停止或激活版本冲突、事实过期或归属不明时不以内存值继续，返回未知。系统恢复顺序由 SYS 拥有；CAP 从持久停止版本和恢复后的当前事实重新给出有效结果。

至少验证累计敞口、部分成交、重复输入、建仓损失预算不被误报成运行时熔断、全仓与逐仓使用同一计划边界和激活归因、多个同向激活分别受限且合计参与账户承载、未知保证金模式失败关闭、停止后保护和退出仍可用、Demo/Live 隔离，以及形成动作责任与发起交易所变更请求前使用同一检查。账户级系统停止还须验证停止版本并发冲突、其他停止类别和损失闩锁保留、证据由服务端产生、没有可闭合激活时保持失败关闭、账户仍有任一持仓或普通/条件订单、另一未完成激活、另一未终态动作、快照后的任一账户场所事实、证据过期、重复释放，以及释放不会恢复计划或产生交易所变更请求。当前字段映射、金额和阈值由代码与 L4 记录。

持仓对齐还须验证减仓与平仓数量边界、部分处置后按本激活成交回算剩余量、账户数量漂移失败关闭、只读凭据不取得写能力、双向持仓不被净额化，以及处置计划不能形成任何入场或追加仓位动作。
