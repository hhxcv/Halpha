# Halpha 交易所动作执行契约

**文档编号：** HALPHA-EXE-002  
**层级：** L3  
**L3 类型：** DOMAIN  
**主要语义所有者：** EXE  
**所属实现模块：** venue_integration 的执行分区  
**语言版本：** zh-CN  
**上位文档或条款：** HALPHA-EXE-001  
**直接依赖：** HALPHA-TRADEPLAN-002、HALPHA-CAP-002、HALPHA-DAT-002  
**直接消费者：** HALPHA-OUT-002、HALPHA-UX-002  
**适用纵向约束：** HALPHA-SYS-001、HALPHA-ENG-001  
**本文档负责：** 外部动作记录、状态、提交、防重复、保护、核对和本地恢复行为  
**本文档不负责：** 计划与激活生命周期、资金计算、事实生产和当前场所参数

## 1. 动作记录

每个外部动作使用一个不可变动作记录，至少保存稳定本地动作身份、环境、账户、激活、来源计划事件、动作类型、规范条款摘要、建立时检查结果、目标订单身份、场所接口支持时的独立请求身份、当前责任状态、外部事实引用、未知原因和闭合引用。新建与重挂订单必须具有稳定场所客户端订单身份；改单和撤单不能虚构交易所并不接受的第二客户端订单身份，而以本地动作身份、原目标身份、期望条款和事实截止点保持幂等责任。

同一环境、激活、来源、动作类型、目标订单身份和规范条款只能对应一个动作。修改、撤单、补保护、减仓和平仓分别形成新动作并引用原因动作，不覆盖原意图和外部身份。多个订单档位共享计划摘要只用于归属和读取，不把各档的提交与未知结果合并成一个动作状态。

## 2. 状态

动作责任只使用以下状态：

- `READY`：动作责任已在本地持久化，尚未向交易所提交变更请求；
- `SUBMITTING`：调用前标记已经提交，此后崩溃按可能调用处理；
- `UNKNOWN`：可能调用或外部事实冲突，只查询原身份；
- `OPEN`：场所已接受或出现部分结果，责任未闭合；
- `NOT_SUBMITTED`：能够证明没有发生外部变化；
- `CLOSED`：该动作对订单、成交、费用、持仓和保护的影响已核对；
- `HANDED_OVER`：用户接管后，Halpha 不再提交或主动查询该动作；它可以表示从未调用的提交责任已交出，也可以表示已调用但结果仍未决的核对责任已交出，不表示成交结果已确定。

场所订单自身状态由 DAT 事实表达，不在动作记录复制第二订单状态机。用户接管时，`READY | SUBMITTING | UNKNOWN` 可以转为 `HANDED_OVER`；已调用动作必须保留请求摘要、调用时间、稳定客户端身份和已有事实引用，清除的只是 Halpha 后续主动查询责任。之后到达的订单、成交和费用事实仍按原身份归属并追加到原动作，不能把 `HANDED_OVER` 当作未成交或零盈亏。已经确认开放的 `OPEN` 动作保持原状态并只读核对。

## 3. 建立与提交

TRADEPLAN 形成不可变动作意图，CAP 返回检查结果，EXE 在本地事务中建立动作记录。需要一次建立同一订单计划的全部 `PlanEvent` 和动作时，薄事务协调器组合 TRADEPLAN 与 EXE 仓储；记录所有权仍分别属于两个领域。事务提交前禁止向交易所请求变更。处理 `READY` 时，执行角色重新读取当前激活和事实、再次调用 CAP、把责任状态持久化为 `SUBMITTING`；新建订单使用动作已保存的场所客户端订单身份，改单或撤单使用已保存的目标身份和期望条款调用唯一执行客户端，再由 DAT 保存结果事实。

执行客户端不得自动重试交易所变更请求。查询可以有界重试，但不能更换动作、身份、目标或条款。`SUBMITTING` 后超时、断线或崩溃进入 `UNKNOWN`。新建订单只查询原客户端订单身份。改单或撤单只有在直接场所响应，或出现晚于调用前目标事实版本或截止点且能证明目标订单取得期望条款或终态的权威事实时，才可确认结果；场所没有独立请求身份，或查询不能区分“请求未到达”和“请求发生后又成交或变化”时，继续保持 `UNKNOWN`，只查询原目标订单及迟到成交。

场所拒绝不自动等于系统故障，也不自动取得重试资格。EXE 只在 maker-only 入场动作已被场所明确拒绝、累计成交为零且没有成交事实时，把“无法作为 maker 执行”归类为可由 TRADEPLAN 消费的正常动作结果并闭合原动作；EXE 不重发该请求。TRADEPLAN 若按 HALPHA-TRADEPLAN-002 形成下一次尝试，必须使用新的稳定动作和客户端订单身份，并重新经过当前事实、CAP 和本节提交路径。参数、权限、余额、工具规则等其他拒绝和无法识别的原因保持原失败结果，不得因文本包含 maker-only 就泛化重试。

默认恢复不得因 `SUBMITTING | UNKNOWN | OPEN` 无进展而重发或建立等价动作。只有风险控制动作超过有界等待、已经查询原身份且仍不能阻止既有风险时，EXE 才可建立一个明确引用前驱的后继：

- 撤单后继必须使用同一目标订单，并有晚于原调用的权威查询事实证明目标订单仍为 `WORKING`；
- 退出后继必须是显式数量的只减仓市价动作，数量不超过新鲜、可归属的单向残余持仓事实。

每个前驱最多一个后继，前驱继续保留并核对迟到事实，后继不能成为下一代前驱。后继结果未知时不再自动发起交易所变更请求，由用户通过官方入口接管。该例外不能用于入场、新建或移动保护、止盈、改单、重挂，也不能作为一般重试机制。

后继记录仍为 `READY`，或已经转为 `NOT_SUBMITTED` 且没有调用证据时，不占用交易所调用次数；提交前持仓变化可以终止旧本地记录，并以新的持仓事实建立带 `LOCAL_REPLACEMENT` 来源的替代后继。任一替代进入 `SUBMITTING` 后，其他本地替代都不能调用交易所。

退出后继只有在权威事实已经使其进入 `CLOSED` 后，才允许处理其建立时点以后新增且精确归属同一激活的入场成交。EXE 汇总这些尚未被清理动作引用的唯一成交事实，最多形成一个 `POST_SUCCESSOR_LATE_ENTRY_CLEANUP` 只减仓市价动作，数量取新增成交合计、当前可归属残仓的较小值；该动作一经建立即占用这些成交预算，无论结果为未知、部分成交、未提交或闭合都不释放，也不能成为后继前驱。后继仍为 `SUBMITTING | UNKNOWN | OPEN` 时不形成该清理动作。

## 4. 部分结果与保护

原生改单只修改当前场所明确支持且仍开放的原订单，并使用独立动作责任记录本次请求；原订单身份和历史条款保持可读。撤销后重挂只有在旧订单终态和取消/成交竞争已经核对后才可形成替代动作。改单或撤单结果未知时按上一节核对目标身份和期望条款，不得同时重挂。减仓和平仓不得超过当前可证明持仓；无法证明不会反向开仓时不提交。

作为减仓、退出或闭合依据的账户持仓事实必须为当前环境和场所的权威查询，精确匹配激活账户、工具、事实截止点和当前数量。目标激活数量由其 `ENTRY` 成交减去自身 `PROTECTION | TAKE_PROFIT | RISK_REDUCTION | EXIT` 成交推导；同账户同工具全部激活按相同规则求和，并与交易所单向净仓严格一致。自动动作数量不得超过目标激活剩余虚拟持仓和交易所同向净仓的较小值，`100%` 只表示目标激活的全部剩余量。CAP 返回未解决的 `SYSTEM_EXTERNAL_ACTIVITY` `NEW_RISK` 停止时，不能因最终净数量碰巧相同而消除冲突；但本段完整归属证明成立时，该停止只阻断新增风险，不得再次覆盖已经通过归属检查的目标激活有界只减仓、既定退出或责任闭合。完整归属证明不成立时，自动账户全仓退出与非接管闭合保持不可归属。

持仓对齐激活是上述 `ENTRY` 推导规则的有界例外，但不制造入场事实。它以 `PositionAlignmentSpec.requested_reduction_quantity` 作为本激活待处置数量；提交前用本激活已经确认的 `RISK_REDUCTION | EXIT` 成交计算已处置量，并要求交易所当前同侧持仓严格等于 `baseline_quantity - 已处置量`。下一动作数量不得超过待处置剩余量或当前同侧持仓，并复用 Nautilus 的唯一 Binance 写适配：单向 `BOTH` 保留 `reduce_only`；双向 `LONG | SHORT` 把不可变持仓侧转换为 Nautilus `position_id`，由适配器按 Binance 双向持仓契约发送 `positionSide`，且不在该模式发送不允许的 `reduceOnly` 参数。Halpha 不另建直连 REST 下单实现。动作持仓侧与事实不一致、账户数量漂移、事实过期、开放委托冲突或凭据不能写时不调用交易所；异步受理、拒绝、超时和未知结果继续进入既有 Nautilus 事件、稳定客户端订单身份与查询核对流程，不能由本地返回伪造成功。全部责任由既有减仓/退出处理器和稳定动作身份承载，不启动入场处理器、资金提供器或订单计划处理器，也不能在失败、重启或部分成交后形成追加仓位。

交易所单向持仓只提供账户净仓，不提供可由 Halpha 强制隔离的计划子仓；`reduceOnly` 只能防止账户净仓被减仓动作反向开仓，不能在交易所内部声明“只减少某计划”。Halpha 的计划边界由稳定订单身份、显式计划剩余量、提交前账户核对以及先撤本计划保护再退出共同实现。若保护触发与撤单恰好竞争，必须按迟到成交重新归因、核对各计划剩余量并失败关闭新增风险；需要交易所层面严格物理隔离时只能使用独立账户或子账户，不能把虚拟归因描述为等价替代。

订单查询、撤单、保护、止盈和改单只使用目标激活动作保存的客户端订单身份；发现同账户其他激活的订单是正常账户事实，不取得操作权。出现非 Halpha 身份、动作归属冲突、虚拟持仓过度扣减、反向激活并存或账户合计不一致时，停止依赖该归属的新增风险和自动扩大动作，保留原身份查询、能够证明的有界减仓及用户接管。

显式退出、时间退出或保护缺口退出在提交目标激活的市价减仓前，先逐一撤销该激活仍在工作的保护和止盈身份并取得目标终态；撤销未决时不提前提交退出。唯一例外是原保护调用结果超过有界窗口仍未知：继续等待同一未知身份不能证明安全，此时允许按目标激活剩余量形成一次只减仓退出，同时继续查询和撤销原身份。共享交易所仓位下移动保护不得让同一激活的新旧保护短时重叠：先确认旧保护终态，再提交已持久化的新保护；只有账户范围不存在其他激活仓位时，才采用新保护工作后撤旧保护的连续保护顺序。任何风险缩减成交都立即触发该激活剩余订单的核对与撤销，不能对其他激活发起批量撤单。

EXE 将无法归属的账户外部活动和已精确归属到 Halpha 动作的数量异常分别形成可核对结果，并请求 CAP 更新有效停止。EXE 不拥有停止版本、来源优先级、重复折叠或释放决定，也不得把动作异常伪装成外部活动。在成交归属和当前持仓算术仍精确成立且 CAP 允许时，已有保护、显式 `reduceOnly` 减仓及一次有界迟到成交清理仍按本契约继续；后续事实由 DAT 原记录保留。

风险敞口出现后，计划所需保护形成独立动作。串行多档在当前实际持仓的保护由场所事实确认前不开放下一档；并行多档只有在预先确认的场所保护能够覆盖所有仍可能成交档位的最大持仓时才可提交。任一入场、撤单或保护结果未知时，尚未提交档位停止，仍开放档位保持累计资金与保护责任直到其终态。保护未知时只查询原身份，不提交内容等价的第二保护。

## 5. 用户控制与闭合

TRADEPLAN 持久化停止、退出或接管决定后，EXE 按当前动作状态处理：停止不再提交增险动作；退出继续处理撤销、保护和减仓动作；接管后不再为该激活发起新的交易所变更请求。尚未确认开放的本地或未决动作转为 `HANDED_OVER`，已确认开放的动作保持原状态并只读核对；两者都继续接收和归属迟到事实，但只有保持原状态的开放动作由 Halpha 主动查询。

动作只有在订单、成交、费用以及对持仓和保护的影响明确，且没有可能已调用但结果未知的责任时闭合。激活整体是否闭合由 TRADEPLAN 消费 EXE 与 DAT 的结果决定。

EXE 可以为完成用户接管后的闭合返回动作终态，并引用 DAT 的最后账户查询事实；CAP 独立判断这些输入能否释放账户级系统停止。释放本身不建立、重开、改变或提交任何 EXE 动作；账户中任一动作仍非终态时，EXE 只能返回当前责任，不能把它包装成释放证据。

## 6. 恢复与验证

系统恢复顺序由 SYS 执行。EXE 在确认唯一执行者并获得恢复调用后读取未闭合动作、查询原客户端身份、保存迟到事实并推进原记录；它不创建恢复状态、第二激活或第二交易所变更请求路径。某激活仍有启动查询身份未决时，最终提交屏障只阻断 `RISK_INCREASING`；已经持久化且精确绑定的撤单、保护、减仓和退出仍须逐项通过当前计划、CAP、账户、工具、方向、外部活动及动作形状检查后才可调用，不能因恢复未决而永久冻结既有风险控制，也不能借此恢复新增风险。

启动批量核对可以对已终结订单与成交使用有界历史窗口，避免场所把很久以前已经终态且无当前影响的记录在每次版本启动时重新制造成“新活动”。该窗口不得限制三类核对：数据库中全部未闭合动作必须逐一查询原身份；交易所当前全部开放普通及条件订单必须读取；当前持仓必须读取并与计划虚拟持仓合计核对。窗口内或实时出现的未归属订单、任一未归属成交、当前开放外部订单或持仓不一致仍按外部活动失败关闭，不能以“历史”名义忽略。

产品当前不持久化第三方执行引擎的进程内订单与持仓缓存，Halpha PostgreSQL 中的计划、动作和事实才是恢复与归属权威。第三方引擎不能因为新进程缓存为空而依据现有仓位或旧成交合成新的外部订单、成交或手续费事实，也不得通过周期批量开放订单检查反复回放已经由 Halpha 独立核对的历史终态订单。账户当前开放订单和持仓由 Halpha 责任边界周期读取，持仓与全部计划已归属成交独立核对；未闭合动作仍按持久客户端身份逐一查询。若第三方启动核对为已知场所订单生成新的进程内客户端身份，EXE 必须先以环境内场所订单身份回溯原已调用 Halpha 动作；只有两种身份都不能归属时才形成外部活动。禁用第三方合成或周期批量修复不能减少当前开放订单、当前持仓和未闭合原身份核对，三者仍按上一段执行。

至少验证事务与交易所调用各故障窗口、重复输入、多档部分提交、部分成交、改单与取消竞争、保护未知、用户控制、数据库不可用、Demo/Live 隔离和唯一交易所请求执行者丢失不会产生未经证明的第二动作或第二次交易所调用；风险控制后继只有在上述新事实成立时产生一次，从未调用的本地替代不增加交易所调用次数，前驱与后继都能被迟到事实核对，后继未知后不会形成链式写入。还应验证错误账户、工具、环境、来源或截止点的持仓事实不能退出或闭合，两个以上同向激活分别保护和退出且 `100%` 不跨计划，撤单不触及其他激活订单，反向激活与账户合计不一致失败关闭，外部活动净额抵消不能冒充 Halpha 归属，账户级 `NEW_RISK` 停止不阻断已经通过完整归属证明的有界减仓、既定退出和闭合，后继后的新增成交清理总量不超过唯一新增成交预算，以及账户级系统停止释放不会改变动作状态、恢复提交或掩盖同账户非终态动作。

持仓对齐还应验证重启只恢复原减仓/退出责任、部分处置后按原基线与唯一成交预算继续、任何账户漂移都在提交前拒绝、`CLOSE` 不越过零反向开仓，以及只读观察、操作预览和计划创建均不会装载执行客户端或产生场所调用。
