# Halpha 阶段性复盘设计

**文档编号：** HALPHA-OUT-003  
**层级：** L3  
**L3 类型：** DOMAIN  
**主要语义所有者：** OUT  
**所属实现模块：** `outcomes`  
**语言版本：** zh-CN  
**上位文档或条款：** HALPHA-OUT-001  
**直接依赖：** HALPHA-OUT-002  
**直接消费者：** HALPHA-UX-002  
**适用纵向约束：** HALPHA-SYS-001、HALPHA-ENG-001  
**本文档负责：** `StageReview` 的固定样本、指标快照、问题判断、改进方案、创建和读取  
**本文档不负责：** 自动归因、策略评分、研究结论、任务创建、交易授权或修改单次复盘  

## 1. 设计结论

阶段性复盘是用户或 AI 对一段已结束计划的总体复盘，不是随交易数据实时变化的仪表盘说明。创建者明确选择事实截止时间范围；OUT 在同一环境内固定该范围命中的每个当前单次复盘版本，并保存当时可可靠计算的总体指标、问题判断和改进方案。后续交易、单次复盘修正或行情变化均不改写该对象。

阶段性复盘与单次计划复盘分别回答“这一笔发生了什么”和“这一组计划暴露了什么问题、下一次准备验证什么”。阶段性复盘只引用单次复盘，不复制成交、动作或场所事实，也不从样本统计自动产生因果结论。

## 2. `StageReview`

`StageReview` 至少包含：

- 稳定身份、环境、标题、创建者和创建时间；
- 用户选择的事实截止时间起点与终点；
- 按单次复盘身份、版本、激活身份、输入摘要和事实截止点固定的来源引用；
- 创建时的计划数、可靠闭合交易数、待评价数、累计净盈亏、累计手续费、累计入场名义金额、累计净回报、胜率和当前连盈或连亏等指标快照，以及各指标的可用范围；
- 用户或 AI 写明的问题判断和改进方案；
- 对全部内容计算的摘要。

范围起点不得晚于终点，且至少命中一项当前单次复盘。指标只使用同一批固定来源中计算完整、已经闭合且费用可归属的交易；缺少可靠分母时累计净回报保持未知，不用部分样本代替完整范围。盈亏、手续费和胜率描述样本结果，不自动证明策略有效或工具存在因果问题。

创建者只能是 `HUMAN | AI`。界面由人创建时记录 `HUMAN`；AI 通过产品创建时必须显式记录 `AI`。问题判断与改进方案均不能为空，但它们只作为后续筛选、研究或开发决策的输入，不自动创建任务、修改策略或发起交易。

## 3. 持久化和重复请求

阶段性复盘创建后只读，不更新或删除。需要修正或采用新的单次复盘版本时创建新的阶段性复盘，并保留旧记录。

创建请求携带调用方稳定的幂等键；相同环境、幂等键和规范内容重复提交返回已有对象，内容不同则拒绝冲突。OUT 本地持久化失败不影响计划、持仓、动作、保护、退出或单次复盘。

## 4. 读取与界面消费

产品按创建时间倒序列出当前环境的阶段性复盘。列表首先显示标题、时间范围、样本量、累计净盈亏、累计净回报和创建时间；问题判断、改进方案、来源范围和指标定义按需展开。实时总体指标仍可作为当前结果摘要显示，但不得把自动变化的分析段落伪装成已经固化的阶段性复盘。

阶段性复盘与交易记录、待评价和全部记录是同一复盘任务中的不同视图。环境切换后必须重新读取对应环境的数据，不能保留或混合上一环境的阶段性复盘。

## 5. 验证重点

- 时间范围只命中同一环境的单次复盘，并固定创建时的精确版本；
- 后续新增交易或单次复盘修正不会改变已有阶段性复盘；
- 可靠交易覆盖不足时相关指标保持未知；
- 人工问题判断和改进方案不会被自动统计改写；
- 相同请求幂等复用，内容不同的幂等键重用被拒绝；
- Demo 与 Live 数据和创建能力保持隔离，Live Read Only 不允许创建；
- 阶段性复盘不创建任务、不修改策略且不产生交易所动作。
